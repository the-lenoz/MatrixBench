# MatrixBench

MatrixBench — библиотека и консольная программа на C++23 для исследования
влияния алгоритма вычисления детерминанта и способа хранения квадратной
матрицы на производительность. В проекте реализованы владение памятью,
матричный фасад, методы Гаусса и Барейса, интерфейс командной строки и тесты.

## Область проекта

Библиотека поддерживает два способа хранения матрицы:

- `ContiguousStorage<T>` хранит все элементы в одной области памяти `T*`;
- `JaggedStorage<T>` хранит отдельно выделенные строки через `T**`.

Для матриц с плавающей точкой детерминант вычисляется методом Гаусса, а для
знаковых целочисленных матриц — алгоритмом Барейса. Общая матричная арифметика
и алгоритм Копперсмита — Винограда намеренно не входят в область проекта.

Контейнеры STL, например `std::vector` и `std::array`, не используются.
Остальные средства стандартной библиотеки разрешены.

Политики хранения и общий для них концепт находятся в независимом модуле
`matrixbench.storage`. Модуль `matrixbench.matrix` содержит только фасад
`Matrix` и публично реэкспортирует модуль хранения. Благодаря этому способ
размещения данных не связан с абстракцией матрицы.

## Требования и сборка

- компилятор C++23 с поддержкой модулей C++;
- CMake 3.28 или новее;
- Ninja.

### CLion и наборы конфигураций CMake

Откройте корень репозитория в CLion и включите поддержку наборов конфигураций
CMake, если среда разработки предложит это сделать. В проекте есть
конфигурации `debug` и
`release`: обе используют Ninja и включают тесты. Соответствующие наборы
сборки и тестирования позволяют собирать нужную конфигурацию и запускать её
тесты обычными действиями на панели CLion.

Полные последовательности конфигурации, сборки и тестирования также можно
запустить из командной строки:

```sh
cmake --workflow --preset debug
cmake --workflow --preset release
```

Компилятор намеренно не закреплён в наборах конфигураций. CLion использует
компилятор из выбранного набора инструментов.

Конфигурация и сборка с Clang:

```sh
cmake -S . -B build-clang -G Ninja -DCMAKE_CXX_COMPILER=clang++
cmake --build build-clang
```

Конфигурация и сборка с GCC:

```sh
cmake -S . -B build-gcc -G Ninja -DCMAKE_CXX_COMPILER=g++
cmake --build build-gcc
```

CMake предоставляет библиотечную цель `matrixbench` и её вариант с
пространством имён `MatrixBench::matrixbench`. Также создаются цель
`matrixbench_cli`, исполняемый файл `matrixbench` и утилита бенчмарков
`matrixbench_bench`.

Тесты охватывают оба способа хранения, правило пяти, безопасность исключений,
делегирование операций из матрицы, оба алгоритма детерминанта, неизменность
входной матрицы, недопустимые допуски метода Гаусса и обнаружение
целочисленного переполнения. Кроме того, CTest запускает 31 сквозной сценарий
для собранной консольной программы, включая все четыре комбинации хранилища и
алгоритма, а также сгенерированные матрицы размера `128 × 128`.

## Использование командной строки

Способ хранения и алгоритм задаются двумя обязательными параметрами:

```sh
./cmake-build/debug/matrixbench --storage contiguous --algorithm gauss
./cmake-build/debug/matrixbench --storage jagged --algorithm bareiss
```

Программа читает из стандартного ввода неотрицательный размер `N`, после
которого должно находиться ровно `N × N` элементов в порядке обхода по
строкам. Пробелы и переводы строк равнозначны. Пример:

```sh
printf '2 1 0 0 1\n' |
  ./cmake-build/debug/matrixbench --storage contiguous --algorithm bareiss
```

Результат:

```text
1
```

Алгоритм `gauss` читает элементы типа `double` и печатает результат с
точностью, достаточной для обратного преобразования. Алгоритм `bareiss` читает
элементы типа `long long` и отклоняет дробные значения. Недостающие и лишние
элементы считаются ошибкой. Краткая справка доступна по команде
`matrixbench --help`.

Коды завершения:

| Код | Значение |
|---:|---|
| `0` | Успешное выполнение или вывод `--help` |
| `2` | Отсутствующий, повторяющийся или неизвестный параметр командной строки |
| `3` | Некорректный, неполный или избыточный ввод матрицы |
| `4` | Ошибка выделения памяти, арифметики, вывода или другого вычисления |

При успешном выполнении стандартный вывод содержит только детерминант и символ
перевода строки. При ошибке стандартный вывод остаётся пустым, а диагностическое
сообщение с префиксом `matrixbench:` записывается в стандартный поток ошибок.

## Использование библиотеки

Клиентский код импортирует модуль детерминанта. Он также реэкспортирует модули
матрицы и хранилища:

```cpp
import matrixbench.determinant;

int main() {
    matrixbench::Matrix<double> matrix{2};
    matrix(0, 0) = 1.0;
    matrix(0, 1) = 2.0;
    matrix(1, 0) = 3.0;
    matrix(1, 1) = 4.0;

    const double determinant = matrixbench::determinant_gauss(matrix);
}
```

Оба способа хранения проверяют переполнение логического количества элементов
`n × n` и выбрасывают `std::length_error`. Метод Гаусса отклоняет
отрицательный или не являющийся конечным `epsilon` исключением
`std::invalid_argument`.
Алгоритм Барейса выбрасывает `std::overflow_error`, если точный результат или
необходимое промежуточное значение невозможно представить типом элементов
матрицы.

Полные контракты модулей, инварианты, обоснование архитектуры и правила
дальнейшей разработки приведены в `AGENTS.md`.

## Воспроизводимые бенчмарки

Набор бенчмарков измеряет ядро библиотеки и консольную программу как два
отдельных эксперимента. Время ядра включает обязательное создание рабочей
копии внутри алгоритма, но не включает подготовку исходной матрицы. Отдельная
серия для хранилищ измеряет создание, заполнение по строкам и глубокое
копирование. Серия командной строки включает запуск процесса, разбор текста,
ввод и вывод, поэтому её значения нельзя напрямую сравнивать со временем ядра.
Скоростные сценарии используют фиксированный безопасный масштаб коэффициентов;
проверки точности и границ применимости остаются в функциональных тестах.

Соберите оптимизированную конфигурацию Clang и запустите быстрый проверочный
набор:

```sh
cmake -S . -B build-clang-release -G Ninja \
  -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release
cmake --build build-clang-release --target matrixbench_bench matrixbench_cli
./build-clang-release/matrixbench_bench \
  --output benchmark-results/quick --mode quick
python3 scripts/run_cli_benchmarks.py \
  --cli ./build-clang-release/matrixbench \
  --output benchmark-results/quick --mode quick
python3 scripts/check_benchmark_results.py benchmark-results/quick
```

Режим `--mode full` проверяет размеры от `1` до `512` и может выполняться
десятки минут. В режиме `quick` используются три выборки и короткая калибровка,
а в режиме `full` — 30 выборок и не менее 200 мс полезного времени на точку.
Фильтр `--filter storage|gauss|bareiss` запускает только одну серию ядра.
Утилита принимает `--seed N` (по умолчанию `20261023`), сохраняет все исходные
замеры в `core_samples.csv`, а сведения о сборке — в `metadata.json`. Скрипт
для консольной программы создаёт `cli_samples.csv` и отдельный файл метаданных.
Каталоги с результатами намеренно игнорируются Git.

Откройте `analysis/matrixbench_report.ipynb` и при необходимости измените
`RESULTS_DIR`. Ноутбук использует только стандартную библиотеку Python, NumPy
и Matplotlib. Он показывает бутстрэп-интервалы, нормированное масштабирование,
влияние раскладки памяти, распределение повторов, стоимость операций с
хранилищем и отдельный график полного времени консольной программы. Проверки
численной точности и поиск границ применимости типов данных в бенчмарки не
входят. Метод Гаусса (`double`) и алгоритм Барейса (`long long`) анализируются
как разные численные эксперименты, а не как прямое сравнение на одном типе
данных.
